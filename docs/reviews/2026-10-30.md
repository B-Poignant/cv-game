## 🔴 Bugs and security (wrong behaviour, exploitable)

- ✅ **Fixed (F-022, 2026-11-03).** **[A] One malformed `move` message crashes the server** — `server/rooms/CvRoom.ts:106`,
  `:348`. _Confirmed._ The handler types the message as `MoveMessage` instead of `unknown`, so
  `send("move", null)` throws `TypeError: Cannot read properties of null (reading 'column')`.
  Colyseus only catches handler errors when the room defines `onUncaughtException`, and
  `server/index.ts` has no process-level guard either: the exception is uncaught and Node
  exits, dropping every visitor in every room. Anyone can do it from the browser console.
  _Fix:_ take `message: unknown` and narrow it (as `handleCollectIntel` does), and add an
  `onUncaughtException` that logs, so a future handler bug can't take the process down.
  Add rejection tests for `null`, a string and an array on `move`, `collect-intel` and `pitch`.
  _Skill:_ `fix-bug`.

- ✅ **Fixed (F-002, 2026-11-03).** **[C] After a resize or a phone rotation, the map is fitted to the old window size** —
  `src/scenes/MainScene.ts:135`, `src/game/Camera.ts:137`; same pattern in
  `src/scenes/MinigameScene.ts:165`. _Confirmed_ in Chromium: going from 1200 to 600 px wide,
  the `resize` handler reads `canvas.width = 1200` (Pixi's `ResizePlugin` only resizes the
  renderer on the next animation frame), so the map stays laid out for 1200 px and overflows
  on the right until the next resize. The e2e test "fills the window when it is resized" only
  checks the canvas size, not the camera. _Fix:_ refit on the renderer's own `resize` event
  (`renderer.on("resize", …)`) instead of `window`'s, and assert the map is centred in e2e.
  _Skill:_ `fix-bug`.

- ✅ **Fixed (F-042, 2026-11-03).** **[D/flow] Closing an unanswered pitch leaves the game paused for good** —
  `src/ui/PitchDialog.ts:138`, `src/ui/PitchFlow.ts:41`. _Confirmed_ (happy-dom). After an
  offer is sent, the dialog's ✕ / Escape just hides it; the map is only resumed when a
  `result` arrives. The server sends nothing when the offer comes after its 60 s window
  (`CvRoom.ts:283`, `PITCH_WINDOW_MS`) or when the connection drops, so the visitor sees the
  map but can't move until they reload. _Fix:_ closing the dialog in the "waiting" stage
  settles the flow and unpauses; the server answers a late offer with a `refused` line
  ("Too slow, I left.") instead of silence. _Skill:_ `fix-bug`.

## 🟠 Debts (works today, will bite)

- ✅ **Fixed (F-010, 2026-11-03).** **[C] Keys stay pressed when the window loses focus** — `src/game/Player.ts:81`. Hold an
  arrow, Alt-Tab, release it elsewhere: no `keyup` reaches the page, and the recruiter keeps
  walking when the visitor comes back. _Fix:_ clear `keys` on `window` `blur` and on
  `visibilitychange` to hidden. _Skill:_ `fix-bug`.

- ✅ **Fixed (F-022, 2026-11-03).** **[A/B] No message rate limit, and the client sends a move every frame** —
  `server/rooms/CvRoom.ts:71` (Colyseus's default `maxMessagesPerSecond` is `Infinity`),
  `src/game/Player.ts:152`. A 240 Hz screen sends 240 `move` messages a second; a script can
  send far more. Each is cheap, but there's no ceiling. _Fix:_ first throttle the client to
  the server tick (`SIMULATION_INTERVAL_MS`, 20 Hz, keeping the last position), then set
  `maxMessagesPerSecond` (e.g. 60). In that order, or legit high-refresh clients get kicked.
  _Skill:_ `fix-bug` + integration rejection test.

- **[B] Losing the connection mid-game isn't handled** — `src/network/MultiplayerClient.ts:38`.
  `onLeave` only forgets the room: the other visitors, Ben and the spam emails stay frozen on
  screen, a visitor slowed by spam stays at half speed (`RemoteSpam` never reports a
  recovery), intel clicks silently do nothing, and nothing tells the visitor. F-023 only
  covers a server that's down at start. _Fix:_ an `onDisconnect` callback that clears the
  remote entities, resets the speed factor and posts to the chat log; reconnection later.
  _Skill:_ `new-feature` (extends F-023).

- ✅ **Fixed (2026-11-03,** `npm audit fix`**; the `elliptic` chain remains).** **[deps] Two high advisories in runtime dependencies** — `body-parser` 2.3.0 (via
  `express`) and `zod` 4.6.5 (via `colyseus`), plus `qs`: `npm audit fix` updates them within
  their ranges. The `elliptic` chain comes from `@colyseus/auth` (unused here) and has no
  non-breaking fix. Don't run `npm audit fix --omit=dev`: its dry run removes the dev tools.
  _Skill:_ `add-dependency`.

- ✅ **Fixed (F-003, 2026-11-03).** **[C] `Building` inlines the iso maths and the tile size** — `src/game/entities/Building.ts:213`,
  `:235`, `:264` (64×32 copied from `src/game/Map.ts:15`). Breaks "grid ↔ pixels only through
  `IsometricConverter`"; changing the tile size would misdraw buildings. Also a French comment
  at `Building.ts:258`. _Fix:_ pass the map's converter to `BuildingFactory` / `Building`.

- ✅ **Fixed (2026-11-03).** **[E] E2E walks by holding keys for fixed times** — `tests/e2e/minigames.spec.ts:14`,
  `tests/e2e/intel.spec.ts:20`. The distance walked depends on the frame rate (`Player` caps
  a frame at 0.1 s), so a slow CI runner can stop short of the building and fail. _Fix:_ a
  helper that walks until the building's intel is in reach (e.g. polls an e2e-only hook or
  the accessible building state), instead of `waitForTimeout`. _Skill:_ `write-tests`.
